## 运行器、判据与隔离

[运行器](../../tests/e2e/multi-device.py) 使用真实 Linux PTY 和
[Android instrumentation](../../apps/android/app/src/androidTest/java/io/github/leonfox28/zterm/MultiDeviceTest.kt)
的私有阶段信号，调用真实 Application repository、Activity、输入、resize 和上传控制器。
它不是 UI 点击覆盖率测试。

核心组每轮 146 项，覆盖连接、配对、detach、接管、断网恢复、跨设备接续、并发和路径变化。
扩展组 88 项覆盖进程／系统故障、会话／授权失效、Android 生命周期、持续输出／输入／
resize 和上传故障。`matrix` 与 `run` 共用筛选规则，支持场景、主机、控制端、路径及重复次数。

连续性比较原 Session ID、shell PID、cwd、shell 变量、后台进程与计数，以及主机命令
执行 nonce。接管后验证旧输入无效、新输入执行一次、旧尺寸不覆盖新控制端。
客户端断线保留远端会话；承载会话的 daemon 崩溃或主机重启则原会话结束，不能静默
创建同名替代。

Direct／Relay 必须有实际选中状态。强制 Relay 阻断三端测试 UID 的双栈非 DNS UDP。
完全断网按测试 UID 和所属 socket 双向隔离，并验证实际丢包；独立守护进程与持久日志
恢复故障规则，管理 SSH / adb 保留。票据经私有文件或标准输入传递，私有失败只保留
允许公开的错误码。并发命令预先分配独立证据文件并串行追加日志。

Linux 冷启动由真实 CLI 启动已停止的 daemon；Android 在新应用进程发起首次主机请求。
独立场景仅提前检查主机本地状态，不预热控制端或 peer。检测上限 120 秒，恢复可输入
上限 60 秒；相关等待共用绝对期限，短时丢包不强制要求出现 reconnecting。
短时故障前启动有界 PTY 输出，故障中只改变尺寸，恢复后核对原会话尺寸与连续性。

结果不确定时先保留只读授权／会话查询，不换操作 ID 自动重发。独立矩阵中，失败配对
或会话变更的旧主机进程必须确认退出，才能隔离后续行；无法确认则保留原始错误并停止
矩阵，剩余行跳过。后续协调器也会在清理未确认时停止，不自动接着运行下一组。

稳定性时钟从 A 的原始 shell 与后台计数建立后开始，准备时间单列；A/B 轮流承载，
A 会话继续存活于 B 阶段。失败后只有只读确认原 ID 仍存在，才可显式重开原 ID 继续
采样；每次失败仍保留，整次验收不会转为通过。结果不确定或原会话消失则停止。
故障条件不足的动作单列 `blocked`；审计拒绝含任何失败、阻塞或跳过动作却声称通过的报告。

运行器／审计最新本地回归 **45 通过**，源码规则和 `git diff --check` 通过。
本次新增清理退出边界、短时双向流量与稳定性状态分类的首次回归分别保存在
`checks/pair-barrier-stop-repro/`、`checks/session-isolation-repro/`、
`checks/short-outage-traffic-repro/`、`checks/soak-status-repro/`。
已完成的 `core-final-09` 固定旧运行器；新行为只能由相应新运行器的记录证明。
